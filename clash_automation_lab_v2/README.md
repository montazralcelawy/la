# Clash Automation Lab v2

تطبيق Windows بواجهة عربية داكنة لإدارة ملفات التعريف ومراقبة ADB وتشغيل مهام محلية متسلسلة على جهاز Android أو محاكي متصل.

## الوظائف المنفذة في صفحة المهام

- فحص اتصال ADB.
- التحقق من تثبيت حزمة اللعبة على الجهاز عبر `pm path`.
- قراءة معلومات النافذة الأمامية عبر `dumpsys window`.
- شرط تحقق `assert_foreground_app` يقارن اسم الحزمة المتوقعة بالنافذة الأمامية؛ عند استخدامه في قائمة المهام، يوقف خيار إيقاف القائمة عند الفشل التسلسل إذا لم تكن اللعبة ظاهرة.
- فتح تطبيق عبر اسم الحزمة (الافتراضي Clash of Clans).
- التقاط لقطة شاشة وحفظها داخل مجلد `screenshots`.
- معاينة أحدث لقطة شاشة من صفحة المهام مع عرض أبعاد الصورة ومسار الملف.
- لمس الشاشة عند إحداثيات X/Y.
- سحب الشاشة من X/Y إلى X2/Y2 مع تحديد المدة بالمللي ثانية.
- الانتظار لمدة محددة، دون الحاجة إلى اتصال ADB.
- إرسال زر الرجوع أو زر الشاشة الرئيسية.
- تشغيل كل المهام ذات الحالة «جاهزة» بالتتابع، مع حفظ الحالة والنتيجة في SQLite وسجل العمليات.
- خيار أمان لإيقاف قائمة المهام عند فشل أي خطوة، مفعّل افتراضياً لتجنب متابعة تسلسل لم تعد شروطه متحققة.
- إيقاف القائمة وطلب إيقاف المهمة النشطة.

## التشغيل على Windows

1. ثبّت Python 3.11 أو أحدث من https://www.python.org/downloads/windows/
2. ثبّت Android Platform Tools عند الحاجة إلى الاتصال بمحاكي أو جهاز Android.
3. افتح CMD داخل هذا المجلد ونفّذ:

```powershell
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python main.py
```

يمكنك أيضاً تشغيل `run_windows.bat` بعد تثبيت Python وPySide6.

## الاتصال بـ ADB

- أضف مجلد `platform-tools` إلى PATH أو حدّد المسار الكامل إلى `adb.exe` من صفحة «إعدادات التطبيق» ثم اضغط «حفظ واختبار ADB».
- اضغط «تحديث الأجهزة» في صفحة المهام؛ يحاول البرنامج الاتصال تلقائياً بمنفذي BlueStacks المحليين 5555 و5556.
- اختر الجهاز الصحيح قبل إنشاء أي مهمة تتفاعل مع الشاشة.
- إحداثيات اللمس والسحب تعتمد على دقة شاشة المحاكي وتخطيط اللعبة؛ اختبرها أولاً على شاشة غير حساسة وتأكد من القيم قبل تشغيل قائمة طويلة.

## البيانات والنسخ الاحتياطي

- ملفات التعريف وإعدادات البوت والمهام مخزنة محلياً في `profiles.db`.
- أنشئ نسخة من صفحة «إعدادات التطبيق» بزر «إنشاء نسخة احتياطية»، أو أوقف البرنامج وانسخ `profiles.db` يدوياً. انسخ مجلد `screenshots` إذا أردت الاحتفاظ بالصور.
- لا تضع كلمات مرور أو رموز تسجيل الدخول في ملفات التعريف.

## إنشاء نسخة Windows EXE

نفّذ `build_exe.bat` من هذا المجلد بعد تثبيت Python. سيبني PyInstaller مجلد تشغيل داخل `dist`. احتفظ بالنسخة المصدرية وبقاعدة البيانات الاحتياطية خارج مجلد البناء.

## حدود مهمة

البرنامج ينفذ أوامر ADB العامة، ويفحص تثبيت اللعبة والنافذة الأمامية، ويحفظ لقطات الشاشة، ويشغّل قوائم مهام متسلسلة مع إيقاف آمن عند الفشل. مع ذلك، خطوة التحقق من التطبيق الأمامي تتحقق من اسم الحزمة فقط ولا تتعرف على عناصر واجهة اللعبة. لا يحتوي هذا الإصدار بعد على نموذج رؤية موثوق يميّز القرية والقتال والأهداف داخل صور اللعبة، ولا على استراتيجية هجومية مستقلة أو منطق تحقق من نتائج البناء والترقيات. إعدادات البوت المخزنة ليست كلها موصولة بمحرك اللعبة؛ لذلك لا ينبغي وصفه بأنه بوت مستقل مكتمل قبل تنفيذ تلك الأجزاء واختبارها عملياً على المحاكي.


## الاختبارات وحزمة Windows

- يوجد اختبار آلي لمحرك المهام في `tests/test_task_page.py` يغطي فحص اتصال ADB، فتح التطبيق، التحقق من تثبيت الحزمة، قراءة النافذة الأمامية والتحقق من التطبيق المتوقع، اللمس والسحب، أزرار الرجوع والرئيسية، الانتظار دون ADB، معالجة غياب ADB، واكتشاف/حفظ لقطة PNG.
- لتشغيل الاختبارات يدوياً من هذا المجلد: `python -m unittest discover -s tests -v`.
- عند دفع تحديث للمستودع، يحاول GitHub Actions فحص تركيب ملفات Python وتشغيل الاختبارات وبناء نسخة Windows محمولة ثم نشرها كـ artifact باسم `ClashAutomationLab-Windows`.
- لتنزيل حزمة Windows بعد نجاح التشغيل، افتح تبويب Actions في المستودع، واختر آخر تشغيل ناجح لـ `Validate and package Windows app`، ثم نزّل artifact `ClashAutomationLab-Windows`. هذه الحزمة تتضمن EXE وملفات التشغيل اللازمة؛ لا تنقل EXE وحده خارج المجلد.
- لا يتضمن البناء قاعدة بيانات شخصية أو بيانات حساب. سيُنشئ البرنامج `profiles.db` بجوار EXE عند التشغيل الأول.
